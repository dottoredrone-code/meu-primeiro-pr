## CapCut operado pelo Claude (D23, K33)
- Para editar ou finalizar um vídeo no CapCut, use a skill do repositório `.claude/skills/capcut-navegador/SKILL.md`:
  o Claude abre o **CapCut web no navegador do Claude** (painel do app desktop), monta cenas, narração, trilha e
  legendas a partir de `saidas\<tema>\capcut\` (gerada por `produzir --capcut` ou `exportar-capcut`), aplica o
  acabamento, exporta `video_capcut.mp4`, mede com a régua do Studio e pede a aprovação do Diego.
- Rode essa tarefa **numa sessão que execute no PC**: app desktop do Claude → Claude Code em modo local na pasta
  `C:\Users\Oem\meu-primeiro-pr`, ou pelo celular via **Dispatch** (Configurações → Sistema → Dispatch, já ligado).
  Sessões do Code na nuvem não usam o navegador do Claude (a tela de Configurações diz: "Não disponível em sessões
  do Code na nuvem").
- Para a janela de arquivos do Windows (enviar e salvar), use o **controle do computador** do app desktop, se a
  versão oferecer; na versão 4.29.0 do Windows ele não apareceu em Configurações → Sistema. Sem ele, o Diego escolhe
  os arquivos quando o Claude pedir, uma pasta por vez.
- O primeiro login no CapCut é do Diego e fica salvo no navegador do Claude. Termos, planos, pagamentos e
  publicações são sempre dele.
- Use só a mídia do Studio no CapCut; recursos de edição (transições, filtros, animação de texto) podem; música,
  sons, banco de vídeo, figurinhas, modelos e fontes da biblioteca do CapCut não (licença comercial não garantida).
  Nada marcado como "Pro".
- Confira a duração total depois das transições do CapCut: se encurtar, a fala e a legenda saem adiantadas.

## Régua medida e benchmark (K12, K13, K14, K31)
- Meça referências com `analisar-referencia "link" -c A` (Gemini assiste pelo link, sem baixar; guarda só números
  e trechos de até 150 caracteres), gere as faixas com `perfil-referencia -c A --salvar` e calibre com
  `nota-referencia` + `calibrar`.
- Leia a calibração assim: diferença constante entre juiz e Diego é **viés** (ajuste a nota mínima, escala 0–100);
  diferença que varia é **discordância** (reescreva a âncora em `config/ancoras.toml` ou troque o juiz).
- Compare ferramentas com `benchmark` (`produzir`, `dados`, `avaliar --doc`): mesma régua do vídeo final para todas;
  custo e tempo do Studio somam todas as execuções, e cada retomada conta como intervenção.

## Aprendizados de engenharia que valem para outros projetos
- Trate todo número vindo de modelo como suspeito: exija finito (`math.isfinite`), dentro da faixa e dentro da
  duração do vídeo; o `json` do Python aceita NaN e Infinity.
- Meça de graça antes de pagar (FFmpeg antes da chamada ao modelo) e deixe o valor medido vencer o estimado,
  inclusive o zero.
- Ao retomar um trabalho, some os números de cada execução; nunca sobrescreva com os da última rodada.
- Arquivo de config que a pessoa edita é entrada externa: valide tipo e ordem e ignore o inválido em vez de cair.
- Gerou TOML ou Markdown à mão? Confira antes de gravar (`tomllib.loads`; células sem `|` nem quebra de linha).
- Relatório que vai para o Git: sem caminho do PC e sem chaves (`mascarar()`).
- Exceção a uma regra do projeto (ex.: mesmo juiz para todos no benchmark, contra D15) precisa aparecer no
  próprio resultado.
